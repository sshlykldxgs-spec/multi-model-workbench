# 回执模板

> **执行方（Codex）每完成一张任务卡，按本模板填写，交给用户。**
> 用户会把回执粘回给指挥方审查 —— 指挥方只看回执与 diff，
> 所以**信息不全等于审查无法进行**，会被退回重填。

---

## 回执

**任务卡**：（填文件名，如 `docs/tasks/P0-收尾.md`）
**结果**：完成 / 部分完成 / 卡住
**提交**：（commit 短哈希）

### 1. 改动文件清单

```
（git diff --stat 的输出原样贴）
```

### 2. 门禁原始输出

**不接受"通过了"三个字。** 逐道贴原始输出。

```
（例如：uv run ruff check . 的完整输出）
```

若某道没跑，写明**为什么没跑**，不要留空。

### 3. 验收标准逐项结果

照抄任务卡里的验收清单，每项标 ✅ / ❌ / 未做，未做要写原因。

| 验收项 | 结果 | 说明 |
|--------|------|------|
| （照抄任务卡） | ✅ / ❌ / 未做 | |

### 4. 修了哪些红，每处的原因

| 报错 | 根因 | 修法 |
|------|------|------|

### 5. 有没有动测试

**必须如实回答。** 改了就说清是哪一条、为什么判断是测试写错而非实现错。
没改就写"未改动测试"。

### 6. 有没有碰铁律

逐条对照 `docs/tasks/README.md` 的铁律速查（R-1 ~ R-7），有触碰就说明。

### 7. 契约有没有变更

有变更就贴 `docs/api-contract.md` 的 diff；没有就写"无"。

### 8. 没能解决的问题

写清现象、你试过什么、你的判断。**卡住就停下来说，不要猜** ——
尤其不要猜 MAF 的 API 用法、中转站能力、以及任何涉及权限与安全的设计。
