## 二、准备 Codex 会话（一次性）

1. 在 Codex 里打开项目目录 `/Users/pengxuezhi/项目蓝图2.0/multi-model-workbench`。
2. 确认它能读到 `backend/AGENTS.md` 与 `frontend/AGENTS.md`（Codex 会自动加载 `AGENTS.md`）。
3. 确认它的 shell 能跑 `uv`、`npm`、`git`，并且 `gh auth status` 是登录态（你刚配好的那套环境）。

**不要给 Codex 装任何通用技能包。** 它需要的全部规范都在项目文件里（A-40）。

## 三、开两个会话，不是一个

| 会话 | 负责 | 第一张卡 | 读哪份 AGENTS.md |
|------|------|---------|-----------------|
| **后端会话** | `backend/**`、`docs/api-contract.md` | P1-A | `backend/AGENTS.md` |
| **前端会话** | `frontend/**` | 等后端 P1-B 的契约出来后再领 | `frontend/AGENTS.md` |

为什么拆两个：两边的门禁、依赖、铁律都不同，混在一个会话里会互相污染上下文。
前端会话**先不要开**——P1-A 纯后端，P1-B 定好模型注册表的接口后前端才有活干。

## 四、每张卡的操作循环

```
① 你：把「启动提示词」粘给 Codex（第一张卡用完整版，后续只换"本次任务卡"那一行）
② Codex：读文件 → 做卡 → 跑门禁 → 按回执模板填回执 → 提交到分支并 push
③ 你：把回执原文粘回给我
④ 我：审（看门禁原始输出、看 diff、对铁律、对验收标准）
   ├─ 通过 → 我更新 PROGRESS.md，给你下一张卡的提示词
   └─ 不通过 → 我写明问题（引用铁律编号与具体行），你粘回给 Codex 重做
```

**③ 粘回执时，请连带贴上 `git log --oneline -3` 与分支名**，我才能去 GitHub 看 diff。

### 让 Codex 开分支而不是直推 main

每张卡一个分支，命名 `p1-a-db-and-login` 这种。做完 push 分支、开 PR，**不合并**。
我审完说"通过"，你再合并。这样 main 永远是审过的代码。
（这条我已写进启动提示词。）

```
- 卡住就停下来说明，不要猜。尤其不要猜 MAF 的 API 用法、中转站能力、以及任何涉及权限与安全的设计
```

## 六、Codex 做 P1-A 时你要准备的

P1-A 要接数据库。Codex 会需要一个跑着的 PostgreSQL（带 pgvector）。两种办法任选：

```bash
cd /Users/pengxuezhi/项目蓝图2.0/multi-model-workbench && docker compose up -d db
```

或让 Codex 自己起。`docker-compose.yml` 已写好，镜像 `pgvector/pgvector:pg16`，连接串在 `backend/.env.example`。

## 七、什么时候来找我

| 情况 | 做法 |
|------|------|
| Codex 交了回执 | 粘给我审 |
| Codex 说卡住了 | 把它的说明粘给我，我判断是改卡还是给它补信息 |
| Codex 想改契约 `docs/api-contract.md` | **必须**先来问我，契约是前后端唯一对齐依据 |
| Codex 想改 `design.md` / `decisions.md` | 不允许，让它把想法写进回执第 8 节 |
| 你自己想调整方向 | 直接说，我改任务卡 |

## 八、P1 四批的先后

```
P1-A 数据库与登录（后端）
  └→ P1-B 模型注册表（后端，定契约）
        ├→ P1-C 三家真实接入（后端）
        └→ 前端会话此时开工：模型下拉、中转站提示（契约已定）
              └→ P1-D 会话持久化与切换（前后端各一半）
```

P1 全部通过后，验收标准是蓝图第 11 节那句：**分别选三家模型发消息；中途切换模型继续聊；刷新后历史还在。** 这一步你亲手点。
