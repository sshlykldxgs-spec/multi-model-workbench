# Codex 启动提示词

> **用户用法**：开一个新的 Codex 会话，把下面「提示词正文」整段粘进去。
> 每换一张任务卡，只需改其中"本次任务卡"那一行。

---

## 提示词正文

```
你是本项目的执行会话。项目根目录：
/Users/pengxuezhi/项目蓝图2.0/multi-model-workbench

开工前按顺序读完这四个文件，读完再动手：
1. docs/handoff-codex.md    —— 铁律、固定流程、审查工作流、沟通约定
2. docs/tasks/README.md     —— 任务卡格式与铁律速查
3. docs/tasks/回执模板.md   —— 做完后按这个填回执
4. docs/PROGRESS.md         —— 当前进度、已知问题、已修过的缺陷

本次任务卡：docs/tasks/P0-收尾.md

硬性要求：
- 一次只做这一张卡。发现别的问题记进 docs/PROGRESS.md 的「已知问题」，
  不要顺手改，不要扩大范围
- 不许改测试来迁就实现。测试红了先判断是实现错还是测试错，
  确认测试本身写错才可以改，并在回执里说明
- 门禁红了就修，修完再跑，直到全绿
- 不要重构没让你动的代码
- 做完按 docs/tasks/回执模板.md 填写回执
- 卡住就停下来说明，不要猜。尤其不要猜 MAF 的 API 用法、
  中转站能力、以及任何涉及权限与安全的设计
```

---

## 为什么这么写

- **读文件放在动手前**：蓝图第 10 节要求"新会话开工前先读 AGENTS.md、design.md、PROGRESS.md"。
  Codex 没有我们前几轮的对话记忆，只能靠文件。
- **"一次只做一张卡"**：对应"小步前进，一个任务一次提交，不跨阶段"。
- **"不许改测试来迁就实现"**：这是 AI 执行方最常见的偷懒方式，
  也是审查最容易漏掉的地方，所以要在提示词里先堵住。
- **"卡住就停"**：比"猜一个能跑的方案"有价值得多。猜测会污染整个代码库。
