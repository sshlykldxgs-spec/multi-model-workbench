## 【实测结果：预判 vs 真实】

当初预判会红的地方**基本都红了**，另外还发现了预判之外的缺陷。对照如下：

| 预判 | 实测 |
|------|------|
| `ruff format` / `ruff check` 会红 | ✅ 中。format 重排 5+2 个文件；check 报 497 个错误，**其中 481 个是中文标点误报**（RUF001/2/3），已配置忽略；剩下 16 个是真错 |
| `pyright` 会报更多 | ✅ 中。8 个错误：`CurrentUser` 未导入、anthropic 的 `temperature` 参数已不存在、openai 的 messages 类型。全部修掉后 0 errors |
| `lint-imports` 可能不识别函数内 import | ❌ **预判错了**。真正的问题是 4 个包**缺 `__init__.py`**，import-linter 直接报 `Module 'app.models' does not exist`；修好后它又开始**追踪传递依赖**，对 R-3 系统性误报。最终改为 AST 自定义门禁 |
| `test_auth` / `test_runs` 等 14 个测试从未跑过 | ✅ 中。全部能跑，只有 1 个失败：`test_me_after_login` —— 因为 `get_current_user` 硬编码了 MEMBER，**管理员被识别成成员**。这是真 bug，不是测试写错 |
| 前端 `tsc` 会有问题 | ✅ 中。2 个错误，都是 `exactOptionalPropertyTypes` 下显式传 `undefined` |

**预判之外还发现**（详见 `docs/PROGRESS.md` 的 18 条）：
mock 条目要求 OpenAI 凭据（会让 mock 验收路径直接死）、ESLint 没有 TypeScript
解析器（lint 从未生效）、`main.py` 直接 import `agent_framework`（违反 R-1）、
`app/core/deps.py` 反向依赖 middleware、契约门禁正则会抓到正文里的非路径文本。

**结论**：不看实际输出就无法判断红在哪。预判的 5 条里错了 1 条，
且完全没预料到"门禁本身是坏的"这一类（3 条）。
