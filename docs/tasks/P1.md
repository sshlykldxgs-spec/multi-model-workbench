# P1 · 多模型对话底座

> 依赖：P0 收尾通过（`P0-收尾.md`）。
> 阶段验收标准（蓝图第 11 节 P1）：
> **分别选三家模型发消息；同一会话中途切换模型继续聊；刷新页面后历史还在。**
>
> 本阶段拆成 4 批。**一批一次提交，不跨批合并。**

## P1 的三条核心约束（先读，后面每张卡都依赖它）

| 约束 | 出处 | 说人话 |
|------|------|--------|
| 消息表是历史的唯一事实来源 | ADR-0002 / R-2 | 不要把 MAF 序列化的会话存起来当历史。每次运行**重建**上下文 |
| 一切模型调用必经 `ModelGateway` | R-3 | 谁都不许直接 import `openai` / `anthropic` / `google.genai` |
| 流式处理不得持有数据库会话 | design.md 12.9.1 | 一次运行可持续数分钟；全程 hold session 会在 15 人时耗尽连接池 |

## P1-A · 接通数据库与真实登录

### 【目标】

重启服务后用户和数据都还在。用数据库里的账号登录，不再是写死的内存账号。

### 【范围】

- 新增：`backend/migrations/versions/*`（首个迁移）
- 改：`backend/app/core/db.py`（连接池参数）、`backend/app/api/v1/auth.py`（改为查库）、
  `backend/app/main.py`（去掉引导管理员）、`backend/app/core/config.py`（连接池配置项）
- 新增：`backend/app/services/users.py`、`backend/tests/test_users.py`

**不碰**：`app/gateway/**`、前端。

### 【约束】

- 密码用 **argon2** 哈希（蓝图第 8 节）。已有 `hash_password` / `verify_password` 可复用。
- 会话 Cookie 必须 **HttpOnly + SameSite**（已有测试盯着，别弄丢）。
- **管理员邀请制，无公开注册**。角色只有 `admin` / `member`。
- **登录不区分"邮箱不存在"与"密码错误"**（已有测试 `test_wrong_password_does_not_reveal_account_existence`）。
- 连接池初始值 `pool_size=10, max_overflow=10`，并在注释里写明 12.9.1 那条硬约束。
- 关键表带可空 `tenant_id`（A-16），**只加列不加逻辑**。

### 【验收标准】

- [ ] `uv run alembic upgrade head` 成功建表
- [ ] `uv run alembic downgrade base && uv run alembic upgrade head` 能来回跑通
- [ ] 用 `admin@example.com` 首次启动时**自动创建**一个管理员（仅当 users 表为空）
- [ ] 登录成功后**重启后端**，会话仍然有效（Cookie 签名不依赖进程内存）
- [ ] 错误密码 5 次后触发限流提示
- [ ] 连续失败登录 15 次返回 `rate_limited`

### 【提交要求】

迁移文件、门禁输出、`alembic history` 输出。

## P1-B · 模型注册表（条目级配置）

### 【目标】

管理员能在数据库里配置模型条目 —— 含官方与中转站 —— 不需要改代码、不需要重启。

### 【范围】

- 改：`backend/app/gateway/registry.py`（从数据库读条目，不再用 `default_entries`）
- 改：`backend/app/api/v1/models.py`（真实 CRUD + 连通性测试）
- 新增：`backend/app/services/models.py`、`backend/tests/test_model_registry.py`
- 新增：迁移（`models` 表已定义，确认字段齐全）

**不碰**：协议适配器内部实现（P1-C 才动）。

### 【约束】

- **条目参数一律显式传入，绝不依赖环境变量推断端点**（design.md 12.8.4）。
  Azure 与 OpenAI 环境变量并存时，通用客户端会优先 OpenAI —— 这是个坑。
- `base_url` 写入前**校验以 `/v1` 结尾**（已有 `_normalize_base_url` 可复用）。
- **能力标记管理员可覆盖**（A-17）。自动探测结果只作**建议值**，
  接口返回时要明确区分"探测到"与"已配置"。
- 凭据只存**引用名**（`credential_ref`），密钥本身从环境变量读，**永不入库明文**（R-7）。
- 个人条目（`owner_id` 非空）仅**本人与管理员**可见。
- `is_relay` 必须返回给前端 —— 界面要提示"数据经第三方转发，能力可能与官方不同"。

### 【验收标准】

- [ ] 管理员能新增一个条目，填写 `base_url`、`credential_ref`、单价、能力标记
- [ ] 填一个不以 `/v1` 结尾的 `base_url`，**提交时自动补全**（不是报错）
- [ ] 普通成员**看不到**他人的个人条目
- [ ] 点"测试连通性"返回探测到的能力，并标注这是建议值
- [ ] 停用一个条目后，它不出现在 `GET /models` 里
- [ ] **停用一个 Gemini 条目时，即使本机没装 `google-genai`，服务也能正常启动**

最后一条是回归测试：P0 修过一个"急切导入导致未配置的协议变成硬依赖"的缺陷，别退回去。

## P1-C · 三家真实模型接入

### 【目标】

选 OpenAI、Claude、Gemini 任一，都能真的收到回答；经中转站的条目也能用。

### 【范围】

- 改：`backend/app/gateway/protocols/openai_compat.py`、`anthropic.py`、`gemini.py`
- 新增：`backend/app/gateway/protocols/tool_calls.py`（工具调用格式归一化）
- 新增：`backend/tests/test_protocols.py`（用 mock 传输层，不打真实 API）

**不碰**：`registry.py` 的读取逻辑（P1-B 已定）、前端。

### 【约束】

- ⚠️ **`openai_compat` 必须用 `OpenAIChatCompletionClient`（`/chat/completions`），
  不是 `OpenAIChatClient`（Responses API）。** 官方文档推荐 Responses API，
  但**多数中转站与自建网关只支持 Chat Completions**。用错了直接连不上。
  这是已核实的事实（design.md 12.8.4），不是偏好。
- **运行前按目标模型能力标记校验**（A-17），不做"跑一半才崩"。
- **降级必须在事件流里明确告知用户**（A-18），不得静默换模型。
  只在**首个片段之前**降级 —— 已产生输出再换会让用户看到两段拼接的内容。
- **已产生输出的流式请求不重试**，避免重复计费。
- 三家都可能有工具调用，格式归一化后要能表达同一语义。

### 【验收标准】

- [ ] 三个条目各发一句话，都能收到回答（P1-C 完成时可先用真密钥手工验一次）
- [ ] 配一个指向中转站的条目，能正常收到回答
- [ ] 配一个**只支持 `/chat/completions`** 的假端点，也能收到回答（证明没用 Responses API）
- [ ] 把某条目的能力标记去掉"流式"，选它会**立刻报错**而不是运行到一半失败
- [ ] 故意让主条目失败，若配了 fallback，事件流里出现**降级提示**
- [ ] 单测覆盖：base_url 补全、能力校验、降级时机、重试边界

### 【提交要求】

三条 gate 的原始输出；真实验收时说明用了哪个服务商（**密钥不要贴进仓库或提交信息**）。

## P1-D · 会话消息持久化与中途切换模型

### 【目标】

蓝图 P1 验收那三条全部成立：三家都能聊、**中途换模型能接着聊**、刷新后历史还在。

### 【范围】

- 新增：`backend/app/services/conversations.py`、`backend/app/services/messages.py`
- 改：`backend/app/api/v1/conversations.py`、`runs.py`
- 改：前端 `frontend/src/pages/WorkspacePage.tsx`（会话列表、历史加载、模型切换）
- 改：前端 `frontend/src/api/client.ts`（新增接口）
- 新增：`backend/tests/test_conversation_switch.py`、前端 `e2e/switch-model.spec.ts`

**不碰**：`app/orchestrator/**`（P4 才动）。

### 【约束】

- **中性格式历史**：消息入库要能表达文本、工具调用、引用（`content` 是 JSONB）。
  不要存任一厂商的原始消息结构 —— 那样就绑死了。
- **切换模型前校验历史兼容性**（design.md 第 4 节）：
  目标模型不支持工具调用而历史里有工具消息 → **明确报错并建议开新会话**，
  **不许静默截断**。
- **裁剪以完整消息为单位**，不得切断工具调用与其结果的配对。
  各厂商约束要遵守（Anthropic 要求首消息为 user、工具结果紧跟对应调用）。
- `usage_logs` 落账，字段齐全：`unit_price_snapshot`、`upstream_model`、`is_fallback`、`cost_center`。
- **A-19**：用个人自备密钥的调用，`cost_center='personal'`，计入个人预算、**不计团队成本**。
- **流式不得长持数据库会话**（12.9.1）。
- 预算：每人 $50/月、$10/日、单次 $2（A-30）。80% 告警、100% 中止。
- SSE 事件带**递增序号**，`GET /runs/{id}/events?after=序号` 能续传。
- 前端类型**由 OpenAPI 生成**，不手写。为每个错误码准备人话提示。

### 【验收标准】

- [ ] 分别选三家模型发消息，都能回答
- [ ] **同一会话中途切换模型继续聊**，上下文连贯
- [ ] **刷新页面后历史还在**（这三条就是蓝图 P1 的验收原文）
- [ ] 在一个有工具调用历史的会话里，切到不支持工具调用的模型，
      **看到明确错误与"开始新会话"的建议**（不是静默截断）
- [ ] 断开网络再恢复，前端能按序号续传补齐缺失事件
- [ ] 把预算调到 $0.01 跑一次，自动中止并给出 `budget_exceeded` 人话提示
- [ ] 用量页能看到本人本月消费与团队成本（两条分开显示）
- [ ] 前端 `npm run typecheck && npm run lint` 全绿

## P1 完成后的整体验收（你亲手点）

1. 登录，选 **OpenAI** 发一句，收到回答
2. 不换会话，改选 **Claude** 继续问同一个话题，回答**用得上上一轮的上下文**
3. 再改选 **Gemini** 继续
4. **刷新页面**，三轮对话都还在
5. 进用量页，看到本次消费已记在**本人**名下
6. 进管理页，能看到每个模型条目的单价、是否中转、能力标记

## 已知会踩的坑（提前说）

| 坑 | 说明 |
|----|------|
| 中转站不支持 Responses API | **必须用 `/chat/completions`**，否则连不上 |
| Azure 与 OpenAI 环境变量并存时优先 OpenAI | 条目参数一律显式传 |
| `base_url` 少了 `/v1` | 已自动补全，但别依赖它掩盖配置错误 |
| 停用条目变成硬依赖 | P0 修过，别退回去 |
| SSE 长持数据库会话 | 15 人时必现，短事务 |
| 静默截断历史 | 蓝图明确禁止，必须报错 |
| token 在 `invoke_agent` span 上重复计数 | P6 会碰；现在先别在 span 上聚合 token |
