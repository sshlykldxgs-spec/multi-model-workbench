## 二、需要你留意的偏差

### D-1 代码任务支持写回与提 PR（范围放大，风险最高）

蓝图 1.0 第 13 节第 6 项的推荐是「上传压缩包或只读克隆仓库，**不做写回和提 PR**」，
第 8 节也把代码任务限定在「沙箱容器内运行，默认不开放外网」。
你选择了**写回并提 PR**，这会把 P0 的权限模型和 P4 的沙箱设计一起改动：

- P0：需要定义仓库凭据模型，并区分只读与读写两级。凭据不能进仓库、不能进数据库明文，必须可轮换。
- P4：沙箱需要一条受控的出网通道到代码托管（GitHub/GitLab），且只允许该目标。
- 新增能力：创建分支、提交、推送、开 PR。这些是**对外可见的副作用**，与会话语义不同：
  一次运行会永久改变远端仓库状态，必须进审计日志，且建议默认仍需人工确认。
- 新增风险：AI 误推、误改默认分支、凭据被提示词注入诱导滥用。缓解方式是
  「分支白名单 + 禁止直推默认分支 + 每次推送前人工确认 + 最小权限 App token」。

**建议**：写回能力与只读能力分两个阶段交付。P4 先只读（蓝图原范围，可验收），
写回与提 PR 作为 P4 的独立增量任务，单独一道验收关。这样 P4 不会因为写回做不完而整体卡住。

### D-2 预算限额没有具体数值（不阻塞）

限额逻辑照蓝图做（每人每日/每月、单次运行上限、80% 告警、100% 中止），
但**默认值留空**，由管理员在配置里设定。首次部署时需要一个保守的初始值，上线前再定。

## 三、已采纳的架构决策（蓝图 1.0 已定，此处仅登记，避免后续反复讨论）

| 编号 | 决策 | 理由 |
|------|------|------|
| A-1 | 业务代码只依赖自研接口，MAF 限制在编排层内 | 框架升级或预览功能变动时影响范围可控 |
| A-2 | 自己的消息表是历史的唯一事实来源，每次运行重建 MAF 上下文 | 中途切换模型需要中性格式历史；MAF 序列化会话能否跨厂商复用未经证实，不依赖 |
| A-3 | 业务数据与向量同一个 PostgreSQL（pgvector） | 小团队运维最省，不额外引入独立向量库 |
| A-4 | 异步任务用 Postgres 任务表 + 独立 worker 进程，不引入 Redis | 文件解析与向量化耗时，不能占用 API 进程 |
| A-5 | 前后端用自定义 REST + SSE 契约，不用 AG-UI + CopilotKit | AG-UI 仍是预览功能，且前端由 AI 生成需要稳定可测试的契约 |
| A-6 | 第一版只用「本进程发起调用」的 MCP，不用厂商托管 MCP | 托管 MCP 的调用由厂商服务发出，白名单、审批、审计日志看不到 |
| A-7 | 工作区与配置区分离，配置只决定「用什么、怎么分工」，不授予权限 | 权限永远按运行者计算，分享配置不能越权 |
| A-8 | Reviewer 与 Worker 使用不同模型或提示词 | 同一模型评自己的输出容易放水 |
| A-9 | 拖拽画布单独成 P5 阶段，基于成熟流程图组件库 | 整个项目前端最重的一块，不让 AI 从零手写 |
| A-10 | 扫描件 PDF 的 OCR 与复杂表格解析第一版不做 | 控制解析工作量 |
| A-11 | 跨会话长期记忆第一版不做，只预留接口 | 控制范围 |

## 五、第二轮补充确认（2026-10-14）

用户在首轮之后追加了五点要求，其中三项是架构级输入。

### 5.1 模型接入必须支持中转站

| 项 | 答复 |
|----|------|
| 接入形态 | **双线支持**：官方直连与第三方中转并存 |
| 主用形态 | **以 OpenAI 兼容协议的中转为主** |
| 影响 | 新增「协议适配器」层，按协议而非厂商划分；条目级 `base_url`、凭据、单价、路由与降级 |

落地见 `design.md` 第 2 节。新增决策 **A-12**。

### 5.2 密钥归属：两者共存

| 项 | 答复 |
|----|------|
| 形态 | 团队统一密钥与个人自带密钥**共存** |
| 影响 | 计量需要两条路径；个人密钥用量是否计入团队预算**待用户确认**（见第七节） |

新增决策 **A-13**。设计要点：凭据挂在模型条目上，条目可多个；
个人密钥走「用户私有条目」，可见范围仅本人与管理员。

### 5.3 收费 / 封控 / 监管：留位 + 蓝图已要求的照做

| 范围 | 做法 |
|------|------|
| 收费 / 计费 | **只留位**：字段、路由、中间件钩子占位，空实现 |
| 封控 / 配额 | **留位 + 蓝图已要求的照做**：预算上限、登录限流、模型白名单按蓝图实现；封号、内容拦截等只留位 |
| 监管 / 合规 | **蓝图已要求的照做**：审计日志全量落地（蓝图第 8 节已要求）；留存期、导出、出境开关只留位 |

新增决策 **A-14**。

### 5.4 开发效率工具清单

| 项 | 答复 |
|----|------|
| 用途 | **两者都要**：既要有开发本项目时用的工具，也要有产品内置的技能系统 |
| 影响 | 产品内置技能系统需要新章节，且涉及 MAF Skills（**仍是预览功能**，与蓝图的「预览功能不进核心路径」冲突，见第七节） |

### 5.5 默认角色与自定义角色

## 六、本轮新增架构决策

| 编号 | 决策 | 理由 |
|------|------|------|
| A-12 | 模型接入按「协议」而非「厂商」划分适配器，支持官方与中转双线，条目级可配 `base_url` / 凭据 / 单价 / 路由 | 中转站只认协议不认厂商；新增中转通常只是加一行配置 |
| A-13 | 凭据挂在模型条目上，团队密钥与个人密钥共存；个人密钥走用户私有条目 | 一个抽象同时覆盖两种归属 |
| A-14 | 收费、封控、监管一律「留位不实现」，但蓝图第 8 节已要求的审计、预算、限流照做 | 符合蓝图「第一版不做收费和多租户」，同时为后续留出扩展位 |
| A-15 | 新增中间件链与策略点（`BudgetPolicy` / `ContentPolicy` / `RateLimitPolicy` / `RoutingPolicy`），第一版挂 `Noop` 或最简实现 | 新功能以「插入中间件」方式加入，不改业务函数 |
| A-16 | 关键表加可空 `tenant_id`，只加列不加逻辑 | 加列近零成本，将来做多租户不必改所有查询 |
| A-17 | 能力标记（流式、工具调用、上下文长度等）自动探测只作建议值，管理员可手动覆盖；运行前按目标模型能力校验 | 中转站实际能力常少于官方，甚至悄悄换模型 |
| A-18 | 模型降级（官方挂→中转兜底）必须在事件流中明确告知，不得静默换模型 | 静默换模型会让用户误判输出可信度 |

## 十、外部事实核实结果（2026-10-14）

核实中发现**蓝图的一处判断正确、一处遗留问题可结案、一处有硬约束**：

1. **蓝图判断正确**：MAF 确实无官方 Postgres 检查点实现，P4 自研是必要的。
   接口形状已明确（`CheckpointStorage` 协议，实现 6 个方法），风险从"未知"降为"已知工作量"。
2. **蓝图遗留问题结案**：OpenCodeReview 的输出**可以稳定结构化解析**
   —— `ocr review --format json --audience agent` 专为 agent 设计。
   蓝图说"P4 前要先做一次小验证"，现在可以更早：`ocr review --preview` 不调模型就能验连通性。
3. **新发现硬约束**：**pgvector 的 HNSW/IVFFlat 索引最多支持 2000 维 `vector`**（halfvec 4000）。
   `text-embedding-3-large` 的 3072 维默认值**无法直接建索引**，必须用 halfvec 或截断维度。
   这是蓝图未提及的约束，已写进 `design.md` 12.5.1。

详细结论见 `docs/design.md` 第 12.1–12.7 节。**仍未核实**：MAF 的 OTel 开启方式、
YAML 声明字段、Skills 机制与稳定状态、各连接器是否支持自定义 `base_url`。
这四项 P0 开工前直接查官方文档与 `samples/`，不要凭印象写代码。
