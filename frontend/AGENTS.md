# AGENTS.md · 前端

> 新会话开工前必读：本文件、`../docs/design.md`、`../docs/PROGRESS.md`、`../docs/api-contract.md`。
> 本文件是前端 AI 会话的工作规则与技术约束。

## 1. 项目一句话

面向小团队内部的多模型 AI 工作台。同一界面用 OpenAI / Anthropic / Gemini，多 agent 协作，
接工具与 MCP，基于上传文件回答问题，兼做通用知识工作与代码任务。

## 2. 你的角色与边界

- 你**只负责前端**：`frontend/`。
- **不要改后端代码，不要自己猜接口**。`docs/api-contract.md` 是唯一对齐依据。
- 需要新接口或字段，**在 `docs/PROGRESS.md` 提出问题**，等后端改契约后再实现。
- TypeScript 类型**由 OpenAPI 自动生成**，不要手写接口类型；接口不一致要在编译期报错。

## 3. 产品结构（两个区域，入口与状态分开）

| 区域 | 做什么 | 谁用 |
|------|--------|------|
| 工作区 | 对话、上传文件、选择已发布的分工、发起运行、查看结果、审批 | 全体成员 |
| 配置区 | 创建角色、画布编排分工、试运行、版本管理、导入导出、分享 | 全体成员，各管各的，可分享 |

两区共用后端，但**入口、界面与数据状态分开**；改配置不得影响正在运行或已完成的任务。
配置区在**独立路由前缀**下（契约里的 `/studio/*`）。

## 4. 技术栈

- React + TypeScript + Vite
- Tailwind CSS + shadcn/ui
- 与后端：REST（OpenAPI 生成类型）+ SSE 事件流
- 画布（P5）：**基于成熟的流程图组件库实现，不要从零手写**（React Flow 一类）
- 类型与检查：`tsc --noEmit`、ESLint、Playwright 端到端烟雾测试

## 5. 开发门禁（不过不算完成）

```bash
npm run typecheck && npm run lint && npm run test:e2e:smoke
# 注意：test:e2e:smoke 需要后端已在 8000 端口运行
# （vite 把 /api 代理到 :8000，Playwright 只自动起前端）。
# 先跑：cd ../backend && uv run uvicorn app.main:app --port 8000
```

另需"生成的类型与契约一致"检查（契约变更后重新生成）。

## 6. UI 验收清单（每个页面都要过一遍，写进 PR 描述）

蓝图第 12 节明确点名前端 AI 开发最常见的遗漏，逐条自查：

- [ ] **空状态**：没有任何数据时的提示与引导
- [ ] **加载中**：骨架屏或进度指示，禁止白屏
- [ ] **错误提示**：为契约里**每一个**错误码准备人话提示，不能只弹"出错了"
- [ ] **断线重连**：SSE 断开后按事件序号续传，界面上有连接状态
- [ ] **长文本与 Markdown**：正确渲染
- [ ] **代码高亮**：代码块与 diff 高亮
- [ ] **手机适配**：至少在窄屏下可用（本项目不做原生 App，但页面需响应式）
- [ ] **审批交互**：写入/破坏性工具调用弹出确认，拒绝后明确显示"未执行"
- [ ] **流式**：逐字显示，不等到整段才渲染

## 7. 关键交互约定

- **运行可续**：刷新页面后能按运行编号重新接上事件流（`GET /runs/{id}/events?after=序号`）
- **运行状态**：排队、运行中、等待确认、成功、失败、已取消 —— 六种状态都要有对应视觉
- **引用可点**：回答里的引用点击后能看到原文位置（文件名 + 页码或段落）
- **不可信内容标注**：文档、网页、工具返回的内容要在视觉上区分于用户与模型的直接输出
- **数据外发提示**：上传内容与对话会发送给所选模型厂商，界面上要标明

## 8. 工作方式

- **不等真实模型**：后端提供 mock 模式，据此先把前端跑通。
- **小步前进**：每阶段拆成若干小任务，一个任务一次提交，不跨阶段。
- 每条提示词包含四点：目标、范围、约束、验收标准；验收标准尽量写成"点击哪里、看到什么"。
- **每次会话结束前更新 `docs/PROGRESS.md`**。

## 9. 禁止事项

- 禁止手写接口类型绕过 OpenAPI
- 禁止在前端持有或透出任何模型厂商密钥
- 禁止把后端返回的文档/网页内容当 HTML 直接注入（XSS 与提示词注入双风险）
- 禁止从零手写拖拽画布
- 禁止跳过门禁提交
